# Registry.index.md — ADIK Partitioned Registry Index

> **Maintained by:** Codebase Analyst Agent (`agents/codebase-analyst.agent.md`)
> **Consumed by:** Builder Agent (`agents/builder.agent.md`), SDK Builder Skill, SDK Consumer Skill
> **Principle:** For large codebases the monolithic `Registry.md` is split into domain-scoped child
> registries. This index is the single entry-point that all agents load first; it declares which
> child registries exist and their aggregate symbol counts so agents can decide which partitions to
> load into context.

---

## Partition Strategy

Registry partitioning is triggered automatically when `Registry.md` exceeds the configured size
threshold (default: **500 symbols** or **200 KB**, whichever is reached first). The Codebase
Analyst Agent detects this during analysis and:

1. Rewrites the monolithic `Registry.md` as `Registry.<domain>.md` files (one per namespace/domain).
2. Creates or updates this file (`Registry.index.md`) as the master index.
3. Prompts the user to enable vectorization if the total symbol count is high (see **Vectorization
   Advisory** below).

Agents MUST load `Registry.index.md` first and select only the partitions they need rather than
loading every child file at once.

## Vectorization Advisory

When the total symbol count across all partitions approaches or exceeds **500 symbols**, agents
MUST surface the following prompt to the user **once per session** (guarded by
`adik.env.json.vectorizationAdvisoryShown`):

> ⚠️ **ADIK Vectorization Advisory**
>
> Your registry currently contains **{totalSymbols}** symbols across **{partitionCount}**
> partition(s). Loading the full registry into agent context on every run will become costly and
> may exceed context-window limits.
>
> **Recommended action:** Enable vectorization so agents can query symbols semantically rather
> than loading every partition.
>
> To enable:
> 1. Set `VECTOR_DB_URL` in your environment (Chroma, Pinecone, Weaviate, Qdrant, pgvector, or
>    Redis Stack are all supported), **or**
> 2. Set `OPENAI_API_KEY` (or equivalent) to use managed embeddings with in-process storage.
>
> Once a vector store is detected, the Codebase Analyst Agent will vectorize the registry
> automatically on the next run.
>
> To dismiss this advisory permanently without enabling vectors, set
> `"vectorizationAdvisoryDismissed": true` in `adik.config.json`.

## Partition Naming Convention

```
Registry.md                  ← monolithic (default / small projects)
Registry.index.md            ← master index (present only when partitioned)
Registry.<domain>.md         ← domain partition, e.g.:
  Registry.users.md
  Registry.payments.md
  Registry.orders.md
  Registry.auth.md
  Registry.shared.md         ← cross-domain types and utilities
```

Domain names are inferred from the top-level namespace/module hierarchy of the source codebase.
They are stored in lower-kebab-case.

---

## Reading Rules for Agents

1. **Always load `Registry.index.md` first** to discover which partitions exist and their symbol
   counts.
2. **Load only the partitions relevant to the current task.** For example, the SDK Builder Skill
   for the `payments` module should load `Registry.payments.md` and `Registry.shared.md` only.
3. **Never load all partitions simultaneously** unless explicitly performing a full rebuild.
4. **Resolve cross-partition type references** by querying `Registry.index.md` for the owning
   partition, then loading that file on demand.
5. **When vector mode is active**, prefer semantic queries over partition loading — request symbols
   by ID or description from the vector store rather than reading Markdown files directly.

---

## Writing Rules for the Codebase Analyst Agent

1. **Partition assignment** is based on the `namespace` field of each symbol entry. Symbols sharing
   a top-level namespace segment are grouped into the same partition.
2. **Shared types** (used by more than one domain) are placed in `Registry.shared.md`.
3. **After writing each partition**, update the Partition Table in this file with the current symbol
   count and timestamp.
4. **Trigger vectorization advisory** when `totalSymbols >= partitionThresholdSymbols` and
   `adik.env.json.vectorMode != "active"` and `adik.config.json.vectorizationAdvisoryDismissed != true`.
5. **Changelog entries** are written to each child registry's own `## Changelog` section; this
   index file does not contain a changelog.

## Usage by Agents and Skills

### Reading a Specific Symbol

```
@skill sdk-builder
registry: Registry.index.md        ← agents pass the index, not individual partitions
language: typescript
```

The SDK Builder Skill resolves partitions internally by:
1. Loading `Registry.index.md` to get the Partition Table.
2. Loading only the required partition(s) for the requested symbols.
3. Resolving cross-partition references by loading `Registry.shared.md` as needed.

### Triggering Partition Refresh

```
@agent codebase-analyst
task: analyse-and-register
target: ./src
output: Registry.index.md           ← pass the index as output target to enable partitioned mode
```
