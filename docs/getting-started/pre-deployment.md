# ADIK Pre-Deployment Walkthrough

> **What this guide covers:** What the ADIK bundle looks like *before* you run it — every file, what it does, and what changes after the first run.

---

## 1. Introduction

When you copy ADIK into your project, nothing happens yet. There is no build step, no install command, and no generated code. You get a set of markdown files and two Python scripts that together form an agentic pipeline — but the pipeline is dormant until you open `ADIK.orchestrator.md` in your AI assistant and let it run.

This guide walks through the bundle file by file so you know exactly what you're adding to your repo.

---

## 2. Bundle Contents

```
your-project/
├── ADIK.md                        ← Standard definition
├── ADIK.orchestrator.md           ← The orchestrator you'll interact with
├── Registry.md                    ← Empty template — will be populated by the Codebase Analyst
├── Registry.index.md              ← For large codebases (activated automatically)
├── agents/
│   ├── builder.agent.md           ← Generates SDK packages
│   └── codebase-analyst.agent.md  ← Scans your source code
├── skills/
│   ├── sdk-builder.skill.md       ← TypeScript, Python, C# generation
│   ├── sdk-builder-tier2.skill.md ← Go, Java, Kotlin (opt-in)
│   ├── sdk-consumer.skill.md      ← Usage examples and boilerplate
│   ├── registry-validator.skill.md ← Validates registry before generation
│   └── vectorize.skill.md         ← Optional vector embeddings
├── scripts/
│   ├── adik-embed.py              ← Self-embeds context into your AI tools
│   └── adik-eject.py              ← Cleanly removes ADIK when you're done
└── mcp/
    └── adik-mcp-server.md         ← Optional MCP server for remote agents
```

All files are plain text (markdown or Python). No dependencies, no binaries.

## 3. File-by-File Walkthrough

### `ADIK.orchestrator.md` — The Orchestrator

This is the only file you interact with directly. When opened in an AI assistant, it drives the entire pipeline: analysis → validation → generation → embedding.

**Key section — the startup prompt your AI will present:**

```markdown
> How would you like to proceed?
>
> **A) Blanket implementation** — I will apply ADIK across all identified
>    areas automatically, using my best judgment for configuration and scope.
>
> **B) Guided implementation** — Before I proceed, please describe any
>    constraints, exclusions, or specific requirements I should follow.
```

**Before:** Contains placeholder text like `[AUTO-FILLED ON DEPLOYMENT]` in the "About This Project" section.
**After:** That section is populated with your project name, tech stack, and SDK targets.

---

### `Registry.md` — The Symbol Registry

The single source of truth for every public symbol in your project. Before ADIK runs, every section is empty — just markers waiting to be filled.

**Key section — empty markers (before):**

```markdown
## Endpoints

<!-- ADIK:ENDPOINTS:START -->
<!-- Entries are auto-generated by the Codebase Analyst Agent. Do not edit manually. -->
<!-- ADIK:ENDPOINTS:END -->

## Classes

<!-- ADIK:CLASSES:START -->
<!-- Entries are auto-generated by the Codebase Analyst Agent. Do not edit manually. -->
<!-- ADIK:CLASSES:END -->
```

**Key section — the symbol schema that entries will follow:**

```yaml
id: string                  # unique stable identifier (e.g. "fn:getUserById")
kind: function | class | interface | enum | schema | endpoint | type
name: string                # canonical name as it appears in the source
namespace: string           # module / package / namespace path
signature: string           # full type signature
description: string         # one-sentence description
parameters: [...]
returns: { type, description }
```

**Before:** All marker sections are empty.
**After:** Every public symbol from your codebase appears as a YAML entry between the appropriate markers.

---

### `Registry.index.md` — Partitioned Registry Index

Only relevant for large codebases (500+ symbols or 200 KB+). When the Codebase Analyst detects the registry is too large, it automatically splits `Registry.md` into domain-scoped files (`Registry.<domain>.md`) and uses this file as the master index.

**Before:** Template with empty partition table.
**After:** (Large projects only) Lists each `Registry.<domain>.md` file with symbol counts.

---

### `agents/builder.agent.md` — The Builder Agent

The primary execution agent. After the registry is populated, this agent validates it, then coordinates SDK generation across all configured languages.

**Key responsibilities (from the file):**

```markdown
1. Resolve registry — monolithic or partitioned
2. Validate the Registry — invoke registry-validator.skill.md. Abort if FAIL.
3. Select generation strategy — API, service, or library templates
4. Invoke the SDK Builder Skill (tier-1) — TypeScript, Python, C#
5. Invoke the SDK Builder Tier-2 Skill (opt-in) — Go, Java, Kotlin
6. Invoke the SDK Consumer Skill — consumption boilerplate
7. Emit a build report — sdk/BUILD_REPORT.md
8. Run self-embedding — update AI context files
```

This file does not change between before and after — it's an instruction set, not data.

---

### `agents/codebase-analyst.agent.md` — The Codebase Analyst

The intelligence layer. This is always the **first** agent to run. It scans your source code and writes everything it finds into `Registry.md`.

**Key responsibilities (from the file):**

```markdown
1. Probe the environment — detect vector DB / RAG capabilities
2. Detect project type — api | service | library
3. Infer framework hints — scan for architecture.md, package manifests, etc.
4. Discover public symbols — exported functions, classes, interfaces, endpoints
5. Populate registry — write symbols in canonical YAML format
6. Detect drift — in incremental mode, emit only changed symbols
```

This file does not change between before and after.

---

### `skills/` — The Five Skills

| Skill | Purpose | Runs when? |
|---|---|---|
| **`sdk-builder.skill.md`** | Generates TypeScript, Python, C# SDK packages. Understands API, service, and library project shapes. | Always (tier-1) |
| **`sdk-builder-tier2.skill.md`** | Generates Go, Java, Kotlin packages. | Opt-in via `tier2Languages` in `adik.config.json` |
| **`sdk-consumer.skill.md`** | Generates usage examples, DI wiring, serialization helpers. Framework hints are auto-inferred. | Always |
| **`registry-validator.skill.md`** | Catches hallucinated or malformed registry entries. **Must pass before any generation.** Outputs `sdk/VALIDATION_REPORT.md`. | Always (mandatory gate) |
| **`vectorize.skill.md`** | Embeds registry symbols into a vector store for semantic search. | Only when `vectorMode = "active"` |

**Tier-2 opt-in example (`adik.config.json`):**

```jsonc
{
  "tier2Languages": ["go", "java"],
  "tier2Options": {
    "go":   { "modulePath": "github.com/<org>/<repo>-sdk-go" },
    "java": { "groupId": "com.<org>", "buildTool": "maven" }
  }
}
```

---

### `scripts/adik-embed.py` — Self-Embedding Script

Deterministic Python script that injects ADIK context blocks into your AI tool configuration files using `<!-- ADIK:START -->` / `<!-- ADIK:END -->` guard markers.

```bash
# Insert or update ADIK blocks in all three context files
python3 scripts/adik-embed.py --action upsert --target .

# Verify all blocks are in place
python3 scripts/adik-embed.py --action check --target .
```

**Files it writes to:**
1. `.github/copilot-instructions.md` — Copilot context
2. `CLAUDE.md` — Claude session context
3. `agents.md` — Agent/skill registration

---

### `scripts/adik-eject.py` — Clean Uninstall

Removes all ADIK artifacts from your project. Safe by default — dry-run first, destructive only with `--confirm`.

```bash
# Preview what would be removed
python3 scripts/adik-eject.py --target . --dry-run

# Remove ADIK framework files (keep generated sdk/)
python3 scripts/adik-eject.py --target . --confirm

# Remove everything including generated SDKs
python3 scripts/adik-eject.py --target . --confirm --remove-sdk
```

---

### `mcp/adik-mcp-server.md` — MCP Server

Optional MCP server that exposes ADIK capabilities (registry queries, SDK regeneration, boilerplate scaffolding) to external agentic environments. Teams that only use ADIK locally don't need it.

## 4. What Happens When You Run ADIK

| Step | What Happens | Files Affected |
|------|-------------|----------------|
| **1** | You open `ADIK.orchestrator.md` and choose **Blanket** or **Guided** mode | `adik.env.json` created |
| **2** | Codebase Analyst scans your source code | `Registry.md` populated with all symbols |
| **3** | Registry Validator checks for issues | `sdk/VALIDATION_REPORT.md` written |
| **4** | Builder Agent generates SDK packages | `sdk/typescript/`, `sdk/python/`, `sdk/csharp/` created |
| **5** | SDK Consumer Skill generates examples | `sdk/<lang>/examples/` populated |
| **6** | Self-embedding runs | `CLAUDE.md`, `agents.md`, `.github/copilot-instructions.md` updated |

---

## 5. Before / After Comparison

| Before (fresh bundle) | After (first run complete) |
|---|---|
| `Registry.md` — empty markers only | `Registry.md` — all public symbols as YAML entries |
| `Registry.index.md` — template | `Registry.index.md` — partition table (large projects) or unchanged |
| No `adik.env.json` | `adik.env.json` — project type, framework hints, vector mode |
| No `adik.config.json` | `adik.config.json` — optional, created only if you chose Guided mode |
| No `sdk/` directory | `sdk/typescript/`, `sdk/python/`, `sdk/csharp/` — full packages |
| No `sdk/VALIDATION_REPORT.md` | `sdk/VALIDATION_REPORT.md` — PASS/WARN/FAIL |
| No `sdk/BUILD_REPORT.md` | `sdk/BUILD_REPORT.md` — summary of all generated artifacts |
| No ADIK blocks in context files | `CLAUDE.md`, `agents.md`, `.github/copilot-instructions.md` updated |

## 6. What Your AI Sees After Self-Embedding

After ADIK runs, your AI context files contain guard blocks like these:

**`.github/copilot-instructions.md`** — tells Copilot what ADIK is and the key rules:

```markdown
<!-- ADIK:START -->
## ADIK — Agentic Development and Implementation Kit

This project uses **ADIK** for automated SDK generation and maintenance.
- **Registry:** `Registry.md` (single source of truth for all public symbols)
- **Build output:** `sdk/` (typescript, python, csharp)
- Never define a type in the SDK that is not first declared in `Registry.md`.
- SDK files in `sdk/` are generated — do not edit them directly.
<!-- ADIK:END -->
```

**`agents.md`** — registers all agents and skills for agentic sessions:

```markdown
<!-- ADIK:START -->
## ADIK — SDK Orchestrator

Loaded agents:
- agents/builder.agent.md
- agents/codebase-analyst.agent.md

Loaded skills:
- skills/sdk-builder.skill.md
- skills/sdk-consumer.skill.md
- skills/registry-validator.skill.md
- skills/vectorize.skill.md (loaded on demand when vectorMode is active)
- skills/sdk-builder-tier2.skill.md (loaded on demand when tier2Languages is configured)
<!-- ADIK:END -->
```

**`CLAUDE.md`** follows the same pattern with an executive summary block.

These blocks are managed exclusively by `scripts/adik-embed.py` — agents never edit them directly. The script is idempotent: running it again updates blocks in place without duplication.
